## Правила формирования коммитов
Одно логическое изменение — один коммит.
Сообщения пишутся на русском языке в прошедшем времени (что *было сделано*, а не что *надо сделать).
**Формат:** `<тип>: <краткое описание>`

*   `feat:` — добавление новой функциональности или нового раздела.
*   `docs:` — изменения, касающиеся только документации (текст, Markdown).
*   `refactor:` — реструктуризация текста или файлов без изменения смысла.
*   `fix:` — исправление опечаток или логических ошибок в требованиях.
*   `chore:` — служебные задачи (настройка репозитория, `.gitignore`).

**Допустимые примеры:**
*   `feat: расписан Use Case оформления заявки`
*   `refactor: реструктуризация раздела «Границы»`
*   `chore: обновлен .gitignore`

**Недопустимые сообщения:**
*   `update`, `fix`, `правки`, `asdf`, `тест` (без контекста и смысла).

## Ветки и ревью
Ветка `main` защищена. Работа ведется в ветках `feature/...`. Изменения попадают в `main` только через Pull Request (PR) после ревью коллеги. Замечания фиксируются в `review_log.md`.
